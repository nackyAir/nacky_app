# ポートフォリオ UI 改善提案

作成: 2026-08-05 / /design-consultation による調査・提案
目的: フリーランス案件獲得。訪問者(クライアント候補)に「この人に任せれば安心してモノができる」を記憶させる。

---

## 1. 現状分析

実機確認: `pnpm dev` → localhost:3000 を 1440x900 でスクロール撮影(home 全section / works/resme / 404 / dark mode)。

### 良い点(壊さないこと)

- 生成り紙 × 明朝ディスプレイのエディトリアル基調は既に上質。方向性は正しい
- セクション番号(01 NOW / 02 ABOUT…)+ 左マージンラベルの情報設計が効いている
- works 詳細の「課題 / やったこと / 成果」構造は営業資料として最強のコンテンツ。信頼感の源泉はここ
- ダークモード(works 詳細)も墨色ベースで破綻していない

### 課題(優先度順)

| # | 課題 | 影響 |
|---|------|------|
| 1 | アクセント色が完全にゼロ。CTA は黒ピルのみ、リンクも墨色 | 視線の焦点がなく「綺麗だが記憶に残らない」の直接原因 |
| 2 | 質感がない。背景が完全フラットな単色 | 「上質な紙」ではなく「薄いベージュの画面」に見える |
| 3 | 404 ページがオフブランド(紫ボタン・汎用レイアウト) | サイト内で唯一の彩度がエラー画面という逆転。信頼感を毀損 |
| 4 | `/works` が 404(`works/[slug]` のみで index が無い) | URL 直打ち・共有時に 3 の画面に落ちる |
| 5 | スクロール連動アニメ依存で、ビューポート外セクションが初期状態で不可視(フルページスクショが白紙になる) | 初回描画の体感・スクショ共有・クローラーに不利 |
| 6 | Hero に「何を頼めるか / 稼働状況」がない(名前+肩書のみ) | クライアントが数秒で判断できない。伝わりやすさ最優先の方針に反する |
| 7 | 明朝と本文書体の役割分担が曖昧(本文まで明朝寄りで長文がやや重い) | 読みやすさ・洗練の伸びしろ |

## 2. リサーチ

### 参考パターン(ミニマル × 色と質感で洗練)

1. **Brittany Chiang** — https://brittanychiang.com
   濃紺ダーク + 単一アクセント + 固定左カラム(現在地ナビ)。色数を絞るほど 1 色が効く見本。信頼感型の代表格
2. **Rauno Freiberg** — https://rauno.me
   ほぼ白黒のミニマルに大胆な色面を一撃だけ置く。「色は面積でなく質で使う」の極北
3. **Awwwards Portfolio 部門** — https://www.awwwards.com/websites/winner_category_portfolio/
   2026 のトレンドは content-first ミニマル + 質感(grain/texture)+ 抑制されたモーション
4. **日本人デザイナー・エンジニアのポートフォリオまとめ (ARUTEGA)** — https://arutega.jp/knowledge/japanese-portfolio/
   和文タイポの詰め(palt / 行間 / 字間)が品質印象を決める、という国内文脈の確認用
5. **Muzli Top 100 Portfolios 2026** — https://muz.li/blog/top-100-most-creative-and-unique-portfolio-websites-of-2025/
   差別化は「派手さ」でなく「一貫した世界観の徹底」で作られている事例群

### 外部デザイン意見(独立 2 視点)

**CODEX SAYS (design direction):** 「静かな職人性」。温かい生成り紙に墨色の精密な組版と**弁柄色 (#9A4635) の校正印**。Newsreader + Shippori Mincho + IBM Plex Sans JP。紙目を CSS の repeating-gradient で入れる。カード UI をやめ一本の編集誌面として組む。スキルのロゴ一覧を廃止し「どの工程に責任を持てるか」で見せる。AI は速度の演出ではなく品質工程(テスト・レビュー・承認地点)の可視化で見せる。

**CLAUDE SUBAGENT (design direction):** 「朱印 — SHUIN」。丁寧に組版された技術文書に**朱肉色 (#C73E1D) の印**が捺されたもの。Instrument Serif + Shippori Mincho B1 + Zen Kaku Gothic New + mono。Works を納品記録の台帳(罫線テーブル)に、AiWorkflow を「原本の写し」(実セッションの断片 + 朱注)に。朱は画面の 1% 未満。

**一致点(=確度が高い)**: 和紙×墨の現路線は正しい / アクセントは伝統色の赤系 1 色を極小面積で / 紙の質感を足す / 本文はゴシック系に分離し明朝は見出し専任 / AiWorkflow は品質プロセスとして見せる / カード的 UI より誌面・台帳的な組版。

## 3. デザイン案(3 案)

### 案 A: 「朱印」 — 現路線の完成形(推奨)

- **コンセプト**: 今の骨格を変えず、「色・質感・組版の一滴」で記憶に残す
- **変更点(セクション単位)**:
  - 全体: アクセント 1 色を導入(朱 `#C73E1D` or 弁柄 `#9A4635`)。使用箇所は「現在地・hover 下線・works の状態マーク・印影モチーフ」の 4 つに限定(画面の 1% 未満)
  - 全体: 紙目テクスチャ(CSS repeating-gradient、opacity 2% 弱)+ 純白/純黒の排除(`#FDFCF9` 紙片 / `#1A1815` 墨)
  - 全体: 本文を IBM Plex Sans JP(または Zen Kaku Gothic New)に分離。明朝はディスプレイ専任。`palt` + 行間 1.9-2.0
  - Hero: 名前の下に「稼働状況(AVAILABLE 等)+ 相談できること 1 行」を追加。数秒で判断可能に
  - Works(home 内): 罫線の美しい「納品台帳」テーブルへ。整理番号・年・案件・役割・状態
  - 404: ブランド組版に置き換え(生成り+明朝+朱)。`/works` index ページを追加
  - アニメ: whileInView の初期不可視をやめ、`clip-path` の静かな開き(420ms)+ reduced-motion 対応
- **参考**: rauno.me(色は質で使う)/ CODEX・SUBAGENT 両提案の一致部分
- **実装コスト: 小〜中**(トークン定義 + 各セクションのスタイル調整。構造変更なし)

### 案 B: 「静かな職人性」 — ポスター再構成

- **コンセプト**: 案 A の土台の上で、Hero とセクション構成を「編集誌面のポスター」に組み直す
- **変更点**:
  - Hero: `100svh` のポスター化。左揃え大組版「設計し、実装し、届けきる。」+ 右端に巨大な弁柄色の `01`。上端に細いランニングヘッダー(名前・稼働状況)
  - SkillList: ロゴ・バッジ的表現を廃止し「01 Frontend / 02 Backend / 03 Product Engineering」の全幅索引行。任せられる工程で整理
  - AiWorkflow: ツール紹介でなく品質工程図(要件→計画→テスト→実装→レビュー→検証)。各工程の成果物と人間の承認地点を明記 →「AI を使っても品質を手放さない」
  - Works: 1 案件ほぼ 1 画面。課題/判断/担当範囲/成果を主役に
  - 案 A の色・質感・タイポは全て含む
- **参考**: brittanychiang.com(固定情報構造)+ CODEX 提案
- **実装コスト: 中**(Hero/SkillList/AiWorkflow の JSX 構造変更を含む)

### 案 C: 「墨のダークファースト」 — 反転による差別化

- **コンセプト**: 墨色 `#1A1815` を基調にした夜の書斎。生成りは文字色側に回す
- **変更点**: ダークをデフォルトに反転。朱アクセントは暗所でより効く。works 詳細(現ダーク)の完成度を全ページに展開。左固定カラム+現在地ナビ(Brittany Chiang 型)
- **参考**: brittanychiang.com
- **実装コスト: 中〜大**(全ページのテーマ再調整+ライトモード側の再設計)
- **リスク**: 和紙の温かみ・親しみやすさを失う。国内クライアント向けの「安心」には案 A/B の紙路線が優位と判断(3 視点とも紙路線を支持)

## 4. SAFE / RISK

**SAFE(カテゴリの期待値、維持するもの)**
- エディトリアル・ミニマル基調と余白 — 「洗練」の土台。ここは動かさない
- 課題/やったこと/成果 のコンテンツ構造 — 信頼の実体。デザインはこれを引き立てる係
- 抑制されたモーション(180-420ms、reduced-motion 対応)

**RISK(顔になる意図的な逸脱)**
- 伝統色の赤系アクセント 1 色を「印」として極小面積で使う — 得るもの: 一目の記憶と和の品格 / 失うもの: 無彩色の完全な静けさ
- Works をカードでなく「納品台帳」として組む — 得るもの: テンプレ感の完全排除、情報密度 / 失うもの: カード UI の慣れた見た目
- AiWorkflow を品質工程図にする — 得るもの: 「AI で速い」でなく「AI でも品質」への転換(発注者の不安に直接応える) / 失うもの: 流行りの AI 演出

---

## 5. 推奨と進め方

**推奨: 案 A を土台に、案 B の Hero + AiWorkflow を第 2 段階として取り込む二段構え。**
理由: 課題の 8 割(色・質感・404・伝わる Hero)は案 A で解消し、構造変更を伴う案 B 要素は効果の大きい 2 セクションに絞ると、リスクなく「綺麗だね」に到達できる。

実装順(案 A 採用時): ① デザイントークン(色/紙目/書体) → ② Hero 稼働状況 → ③ 404 + /works index → ④ 納品台帳 → ⑤ アニメ差し替え
