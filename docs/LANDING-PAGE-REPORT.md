# ポートフォリオ LP 品質監査

対象: `/home` (Naoki Hayashida ポートフォリオ)
計測日: 2026-08-03
計測環境: 本番ビルド (`next build` → `next start -p 3100`)、Chromium headless、375x812 / 1280x900

## スコープの注記

このスキルは広告キャンペーンのLP監査用。このサイトには稼働中の広告キャンペーンが無いため、
以下の項目は**対象外**として評価していない (該当データが存在しないため):

- Message Match (広告コピーとLPの一致度)
- UTM / クリックID (gclid, fbclid 等) のハンドリング
- コンバージョンピクセルの発火検証
- 動的キーワード挿入・地域別出し分け

代わりに Message Match の枠は「**流入時の見え方の一致**」として評価した。
このページの主な流入は SNS / DM でのURL共有なので、共有時のプレビューカードが
広告クリエイティブに相当する役割を持つ。この置き換えは評価者の判断であり、
スキル定義そのままではない。

CV ゴールは「お問い合わせフォーム送信」1点として評価した。

## 指摘事項 (影響度順)

### 1. OG画像が404 — 共有プレビューが全て壊れている

`app/layout.tsx` は `/og-image.png`、`app/(children)/home/page.tsx` は `/og-home.png` を
参照しているが、`public/` にどちらも存在しない。

```
404  /og-image.png
404  /og-home.png
200  /api/og        ← 動的OG生成ルートは正常
```

X / Slack / LINE / Discord で `nacky.me` を共有した時、プレビューカードの画像が
出ない状態。ポートフォリオはDM共有で人に見せる場面が多いので、
「最初に目に入るクリエイティブ」が毎回欠けていることになる。

**修正案**: metadata の `images` を `/api/og` に向ける (すでに200を返す)。
静的PNGを置く方針にするなら `public/og-image.png` と `public/og-home.png` を作る。
どちらを正とするかは方針判断が要るので未着手。

### 2. フォームの摩擦が大きい

入力コントロール9個は、スキルの基準表で最下位帯 (`9+ fields → Lowest CVR`、
高単価オファー限定で許容)。ポートフォリオの初回接触としては重い。

内訳の問題:

- **メールアドレス確認用**: コピペで埋められるのが実態で、摩擦だけ増える
- **電話番号が必須**: 初回問い合わせで電話番号を要求されると離脱要因になる。任意で足りるはず
- **autocomplete属性がゼロ**: 全フィールドで未設定。モバイルの自動入力が一切効かない。
  `autocomplete="name" / "email" / "tel" / "organization"` を付けるだけで入力負荷が下がる
- **送信ボタンが初期 `disabled`**: `!form.formState.isValid` で無効化 + `mode: 'onBlur'`。
  何も触っていない状態でグレーアウトしており、押して理由を知ることができない。
  押せるようにして、送信時にエラーを出す方が親切
- **ボタン文言が `送信する`**: スキル基準では具体的な文言を推奨 (例: `この内容で問い合わせる`)

どのフィールドを削るかは「Naokiがどの情報を受け取りたいか」の判断なので未着手。

### 3. 主要CTAのタップターゲットが20px

ヒーローの3導線 (`お問い合わせ` / `プロジェクトを見る` / `経歴書`) が高さ20pxのテキストリンク。
基準は48×48px以上。**このページで最も押してほしい要素が最も押しにくい**状態。

CTA自体は3つともファーストビュー内に収まっている (モバイル375×812で確認済み) ので、
位置は問題なし。当たり判定だけの話。

同様に個人情報チェックボックス16×16、送信ボタン高さ40pxもCV直前の操作なので効く。

### 4. アバター画像が1000×1000 / 144KB

62pxで表示している画像に144KB使っている。ページ総転送量624KBの23%。
`next/image` を通していない生の `<img>` なので最適化も効いていない。

128px幅のWebPにすれば5〜8KB程度。さらに `width`/`height` 属性が無いため
読み込み時にレイアウトシフトが起きうる (CLS実測は未取得)。

`src="./avatarImage.jpg"` の相対パス指定も、URL末尾にスラッシュが付くと解決先が
変わるので `/avatarImage.jpg` にした方が安全。

### 5. モバイルメニューのナビ2枚が死にリンク

`#about` / `#skills` に対応する `id` がページに無い。4枚中2枚が無反応。
(旧実装の `Section` にも `id` は無かったので、今回の書き換えで発生したものではない)

### 6. 閉じたドロワー内の8要素がフォーカス可能

`MobileMenu` のドロワーは閉じている間 `y: 100%` で画面外に出るだけで、
DOMからは消えずフォーカス可能なまま (リンク・ボタン計8個)。
キーボード操作・スクリーンリーダーで見えない要素を辿ることになる。
`inert` 属性か条件付きレンダリングで解決する。

視覚的には画面外なので、通常のタップ操作への影響はない。

### 7. 軽微

- 本文が15.2px (`text-[0.95rem]`)。基準の16pxをわずかに下回る
- `MobileMenu` のフッターが `© 2024` 固定。ページフッターは動的年 (`2026`) で不一致
- プライバシーポリシーページへのリンクが無い。フォームに個人情報の取扱い文はあるが、
  独立したポリシーページへの導線は無し

## Quick Wins (推奨着手順)

| # | 対応 | コスト | 効く理由 |
|---|---|---|---|
| 1 | OG画像を `/api/og` に向ける | 2行 | 共有時のプレビューが全て復活 |
| 2 | 全入力に `autocomplete` 付与 | 7行 | モバイル自動入力が有効化 |
| 3 | 電話番号を任意化 + 確認用メール削除 | 小 | 必須9→7個。離脱の主因を除去 |
| 4 | ヒーロー3CTAに `py-3` 等で48px確保 | 小 | 最重要導線の当たり判定 |
| 5 | 送信ボタンの `disabled` 解除 | 1行 | エラー理由が分かるようになる |
| 6 | アバターを `next/image` + 128px WebP | 小 | -135KB、CLSリスク解消 |
| 7 | About / Skills セクションに `id` 付与 | 2行 | 死にリンク解消 |
| 8 | 閉じたドロワーに `inert` | 1行 | a11y |

1・2・4・5・7・8 は方針判断を含まないので即実行可能。
3 は受け取りたい情報の判断、OG画像の静的/動的の選択は 1 の中の分岐。
