## 1. 現状のUIデザイン分析

### 構造

```
Header (fixed) ─ ロゴ "N" + 名前 / ナビ = X・Instagram・Github のみ
│
main (max-w-2xl = 672px 単一カラム, pt-32)
├─ Hero      アバター64px → 名前(36-48px) → 肩書(mono) → 紹介文2行 → テキストリンク3本
├─ About     段落2つ（技術スタックの一般論）
├─ Skills    dl 4行（Frontend / Backend / Mobile / Database）
├─ Projects  受託3件 + 個人2件、各 期間/役割 → タイトル → 説明1行 → 技術タグ
├─ Contact   入力9項目のフォーム
└─ Footer    SNS3つ + コピーライト
```

### デザイン言語の実態

| 要素 | 現状 | 評価 |
|---|---|---|
| フォント | Geist Sans + Geist Mono | 2024-25の開発者ポートフォリオで**最も使われている組み合わせ**。個性ゼロ |
| 配色 | slate 系グレースケールのみ、**アクセントカラーなし** | 目線の誘導が効かない。CTAが本文と同じ重さ |
| レイアウト | 全セクション 672px 単一カラム・左揃え・`mt-24` 統一 | リズムがなく、どこも同じ密度。スクロールしても「進んでいる感」がない |
| 区切り | hairline border のみ | 上に同じ |
| タイポスケール | h1 36-48px / 本文 15.2px / ラベル 12px の3段 | 対比が弱い。本文が基準の16pxを下回る |
| モーション | 同一の `fade + y:12 / 0.4s` を6箇所で使い回し | 演出として認識されない。あってもなくても同じ |
| 背景 | 純白 / `slate-950` ベタ | 質感・奥行きゼロ |
| 差別化要素 | **なし** | 「見た記憶が残るもの」が1つもない |

一言でいうと **Vercel系ミニマルテンプレートの最大公約数**。破綻はないが、
「この人に頼みたい」「この人と働きたい」を生む要素が実装されていない。

### 情報設計の問題（こちらが本丸）

ページ全体が **「何を使えるか」しか語っておらず、「何にコミットしているか」を語っていない**。

- Hero の紹介文: 「使いやすさとコードの品質を大切にしています」→ 誰でも言える
- About: 「最新の技術トレンドをキャッチアップしながら〜総合的な視点で」→ 主語が誰でも成立する一般論
- Skills: 技術名の羅列のみ。**業務で3年使ったReactと、触ったことがあるNestJSが同じ重さで並んでいる**
- Projects: 説明がタイトルの言い換え

  > 「業務委託先の会社様の勤怠管理アプリケーションを開発」

  課題も、担当範囲も、判断も、結果も書かれていない
- **「今なにをやっているか」のセクションが存在しない** — 継続性・熱量が最も伝わる枠が空いている
- 実績を裏付ける数字が1つもない（経験年数・関わったプロダクト数・チーム規模など）

### 導線の問題

- ヘッダーのナビが **SNS3つだけ**。セクションナビも常設CTAもない
- Instagram（コーヒー用アカウント）が職務用ナビに並んでいる
- ヒーローのCTA3本が全部テキストリンク・同じ見た目 → 主従がない
- `/blog` は **Coming Soon のまま**（LPから繋ぐ価値はまだない。中身を作るか、導線から外すかの判断が必要）
- `/resume` への導線が小さいテキスト1本のみ

## 2. 改善点リスト

優先度: **A = LPの伝わり方に直結 / B = 印象を決める / C = 品質の底上げ**

### A. 情報設計・コンテンツ（最優先）

| # | 改善点 | AsIs → ToBe |
|---|---|---|
| A-1 | **Hero に主張と証拠を置く** | 名前+肩書だけ → 「何をする人か」の一文 + 証拠数字3つ（経験年数 / 関わったプロダクト数 / 主領域）+ 主CTA1つを明確化 |
| A-2 | **Now（現在地）セクションを新設** | なし → 今取り組んでいること（インターン継続中の内容・個人開発・学習中の領域）。「コミットしていること」が最も伝わる枠 |
| A-3 | **How I work（仕事の進め方・価値観）を新設** | なし → 3〜4個の原則を具体で。例: 「TDDで先にテストを書く」「shadcn/uiを優先して車輪の再発明をしない」「型で壊れない状態を作る」 |
| A-4 | **Projects を 課題 → やったこと → 結果/学び の3層に** | 説明1行（タイトルの言い換え） → 各案件で担当範囲・技術選定の理由・数値/学びを明記 |
| A-5 | **Skills に習熟度と使用文脈を付ける** | フラットな羅列 → 「業務で◯年 / 個人開発で使用 / 学習中」の3段階に分離 |
| A-6 | **About を一般論から一人称の話に書き換え** | 「最新技術をキャッチアップしながら〜」 → なぜフロントエンドなのか、何を面白いと思っているか |
| A-7 | GitHub活動の可視化を復活 | 削除した `LanguageProgress` の代わりに、コントリビューション/言語比率などの継続性の証拠（要: API方針の判断） |
| A-8 | `/blog` の扱いを決める | Coming Soon のまま放置 → 中身を作ってLPに繋ぐ or 当面は導線から外す |

### B. ビジュアル・デザイン言語

| # | 改善点 | AsIs → ToBe |
|---|---|---|
| B-1 | **フォントを差し替える** | Geist（開発者ポートフォリオの最大公約数） → 見出しに個性のある書体、日本語も専用書体を指定（現状は日本語フォント未指定でOS依存） |

| B-3 | **セクションごとに幅と密度を変える** | 全部672px単一カラム → 読み物は狭く / Projects は広く / 区切りにフルブリード。スクロールにリズムを作る |
| B-4 | **タイポの対比を強める** | h1 48px止まり・本文15.2px → display をもっと大きく、本文は16-17px/行間1.9 |

## 3. 提案する構成（案）

```
Header  ロゴ / セクションナビ / [お問い合わせ] 常設CTA
│
Hero    主張の一文 (大きく)
        証拠数字 3つ ── 3年 / ◯プロダクト / フロントエンド
        [お問い合わせ]（主）  経歴書を見る（副）
│
Now     いま取り組んでいること ← 新設
│
Work    仕事の進め方・大事にしていること 3〜4原則 ← 新設
│
Skills  習熟度つき（業務 / 個人 / 学習中）
│
Projects 課題 → やったこと → 結果 の3層 + 技術選定の理由
│
Output  GitHub活動 / 発信 ← 要判断
│
Contact 軽量化したフォーム + 返信目安 + 相談できる内容
│
Footer  SNS / コピーライト
```

## 4. アートディレクション 3案

いずれも「Geistミニマル」から抜ける方向。**推奨は案1**。

### 案1: エディトリアル（技術誌・作品集） ★推奨

- 見出しに明朝/セリフ、本文はサンセリフ。番号付きセクション、太いルール線、余白で読ませる
- 配色: オフホワイト地 + インク + 差し色1（朱 or 深緑）
- モーション: 控えめ。スクロールに応じたセクション番号の切り替わり程度
- **合う理由**: 今回の改善の本丸は「文章で取り組みを伝えること」。読ませるための版面設計が最も効く
- リスク: 日本語書体の選定を外すと一気に古臭くなる

### 案2: エンジニアリングログ（ターミナル/ブルータリスト）

- 等幅主体、ダーク基調、グリッド線を可視化、ASCII的な区切り、hoverでコマンド風の反応
- 配色: 濃色地 + 蛍光の差し色1
- **合う理由**: エンジニアとしての人格が最も強く出る。記憶に残りやすい
- リスク: 現状も mono を多用しているので、**中途半端にやると「今と同じ」になる**。振り切る前提

### 案3: プロダクト志向（ライト/ウォーム）

- 温かいオフホワイト、大きめカード、**プロジェクトの実スクショ**、やわらかい影とマイクロインタラクション
- 配色: クリーム地 + 彩度低めのアクセント
- **合う理由**: 「作れる人」より「プロダクトを届ける人」に見える。受託の引き合いには強い
- リスク: スクショ素材が必要（NDA案件は出せない可能性あり）
